# 大模型预训练完整流程解析

> 基于 MiniMind 项目的 `trainer/train_pretrain.py` 进行逐步拆解。
> 适合前端开发者初学大模型时建立"从数据到模型"的全局认知。

---

## 一、总览：预训练到底在做什么？

用一句话概括：**给模型喂大量文本，让它学会"给定前面的字，预测下一个字"。**

这个任务叫做 **Next-Token Prediction（下一个 token 预测）**，是几乎所有大语言模型（GPT、LLaMA、DeepSeek...）的预训练目标。

```
输入:  "今天天气"
标签:  "天天气真"   ← 每个位置的"正确答案"是它右边那个字
预测:  "天天气好"   ← 模型的预测
损失:  只有最后一个位置预测错了（"好" ≠ "真"），loss 较大
```

训练的本质就是不断缩小"预测"和"标签"之间的差距（即降低 loss）。

---

## 二、完整流程九步走（宏观）

```
┌──────────────────────────────────────────────────────────────────────────┐
│  1. 初始化环境（分布式 + 随机种子）                                        │
│  2. 配置模型参数（MiniMindConfig）+ 检查断点                              │
│  3. 设置混合精度（AMP）                                                  │
│  4. 配置实验追踪（wandb / swanlab）                                      │
│  5. 创建模型 + 分词器 + 数据集 + 优化器 + GradScaler                      │
│  6. 从 checkpoint 恢复状态（断点续训）                                    │
│  7. DDP 包装模型（多卡并行）                                              │
│  8. 训练循环（epoch → step → forward → backward → update）              │
│  9. 清理分布式进程                                                       │
└──────────────────────────────────────────────────────────────────────────┘
```

## 四、逐步深入解析

### 第 1 步：初始化环境和随机种子

**目的**：确保多卡训练时各 GPU 正确通信，并保证实验可复现。

```python
# 初始化分布式训练环境
local_rank = init_distributed_mode()
# 如果是多卡训练，把 device 设为当前 GPU
if dist.is_initialized():
    args.device = f"cuda:{local_rank}"
# 设置随机种子（不同 GPU 加不同偏移量，确保数据打乱不同）
setup_seed(42 + (dist.get_rank() if dist.is_initialized() else 0))
```

**`init_distributed_mode` 做了什么：**

```python
def init_distributed_mode():
    if int(os.environ.get("RANK", -1)) == -1:
        return 0  # 非 DDP 模式，直接返回

    dist.init_process_group(backend="nccl")  # 用 NCCL 后端初始化进程组
    local_rank = int(os.environ["LOCAL_RANK"])
    torch.cuda.set_device(local_rank)        # 每个进程绑定一块 GPU
    return local_rank
```

> **前端类比**：就像 Web Worker 各自有独立的线程，这里每块 GPU 各自跑一个进程，NCCL 相当于 `postMessage` 让它们通信。

**`setup_seed` 做了什么：**

```python
def setup_seed(seed: int):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
```

> 设置所有随机数生成器的种子（Python 内置、numpy、torch CPU/GPU），并关闭 cuDNN 的非确定性优化，确保同样的代码 + 数据每次运行结果一致。

class MiniMindConfig(PretrainedConfig):
    model_type = "minimind"

    def __init__(
        self,
        dropout: float = 0.0,           # Dropout 概率

        vocab_size: int = 6400,          # 词表大小

        rope_theta: int = 1000000.0,     # RoPE 基频

> **关键概念**：Config 就像前端组件的 `props`，一次性定义好模型的所有"规格参数"，后续的模型构建、保存、加载都依赖它。

### 第 3 步：设置混合精度（AMP）

**目的**：用较低精度（float16/bfloat16）计算以节省显存、提升速度，同时几乎不影响训练效果。

```python
device_type = "cuda" if "cuda" in args.device else "cpu"
dtype = torch.bfloat16 if args.dtype == "bfloat16" else torch.float16

# CPU 不支持混合精度，用空上下文替代
autocast_ctx = (
    nullcontext() if device_type == "cpu"
    else torch.cuda.amp.autocast(dtype=dtype)
)
```

> **精度对比**：
> - `float32`（全精度）：32 位，精度高但占显存多
> - `float16`（半精度）：16 位，省显存但数值范围小，容易溢出
> - `bfloat16`（脑浮点）：16 位但指数位更多，数值范围和 float32 一样大，推荐使用
>
> 混合精度不是"全部用半精度"，而是"能用半精度的地方用半精度（如矩阵乘法），必须全精度的地方保持全精度（如 loss 计算、归一化）"。

### 第 5 步：创建模型 + 分词器 + 数据集 + 优化器

这是最核心的初始化步骤，包含 5 个子环节。

#### 5.1 初始化模型和分词器

```python
model, tokenizer = init_model(lm_config, args.from_weight, device=args.device)
```

**`init_model` 做了什么：**

```python
def init_model(lm_config, from_weight='pretrain', tokenizer_path='../model',
               save_dir='../out', device='cuda'):
    # 1. 加载分词器（词表在 model/tokenizer.json）
    tokenizer = AutoTokenizer.from_pretrained(tokenizer_path)

    # 2. 根据 config 创建模型
    model = MiniMindForCausalLM(lm_config)

    # 3. 如果指定了预训练权重，则加载（迁移学习/继续训练）
    if from_weight != 'none':
        weight_path = f'{save_dir}/{from_weight}_{lm_config.hidden_size}.pth'
        weights = torch.load(weight_path, map_location=device)
        model.load_state_dict(weights, strict=False)

    # 4. 打印参数量
    get_model_params(model, lm_config)
    return model.to(device), tokenizer
```

> **分词器的作用**：将人类可读的文本 → token id 序列（整数数组）。
> 例如 `"你好世界"` → `[3021, 1567, 892, 4523]`
> 模型只能处理数字，不能直接处理文字。

#### 5.2 可选：torch.compile 编译加速

```python
if args.use_compile == 1:
    model = torch.compile(model)
```

> PyTorch 2.0+ 的特性，将动态计算图编译为静态优化代码，可提速 10%-30%。类似前端的 AOT 编译（如 Svelte 的编译策略 vs React 的运行时策略）。

#### 5.3 创建预训练数据集

```python
train_ds = PretrainDataset(args.data_path, tokenizer, max_length=args.max_seq_len)
```

**`PretrainDataset` 的完整实现：**

```python
class PretrainDataset(Dataset):
    def __init__(self, data_path, tokenizer, max_length=512):
        self.tokenizer = tokenizer
        self.max_length = max_length
        # 用 HuggingFace datasets 加载 jsonl 格式数据
        self.samples = load_dataset('json', data_files=data_path, split='train')

    def __getitem__(self, index):
        sample = self.samples[index]

        # 1. 分词：文本 → token ids（不加特殊 token，预留 2 个位置）
        tokens = self.tokenizer(
            str(sample['text']),
            add_special_tokens=False,
            max_length=self.max_length - 2,
            truncation=True
        ).input_ids

        # 2. 手动加 BOS（开始符）和 EOS（结束符）
        tokens = [self.tokenizer.bos_token_id] + tokens + [self.tokenizer.eos_token_id]

        # 3. 右侧补齐 PAD 到固定长度（batch 内所有样本必须等长）
        input_ids = tokens + [self.tokenizer.pad_token_id] * (self.max_length - len(tokens))
        input_ids = torch.tensor(input_ids, dtype=torch.long)

        # 4. 构造 labels：克隆 input_ids，PAD 位置设为 -100（不计算 loss）
        labels = input_ids.clone()
        labels[input_ids == self.tokenizer.pad_token_id] = -100

        return input_ids, labels
```

**数据处理流程图解：**

```
原始文本:   "今天天气真好"

分词后:     [2156, 1034, 892, 5567]      ← token ids

加特殊符:   [BOS, 2156, 1034, 892, 5567, EOS]

padding:   [BOS, 2156, 1034, 892, 5567, EOS, PAD, PAD, PAD, PAD]

input_ids: [BOS, 2156, 1034, 892, 5567, EOS, PAD, PAD, PAD, PAD]
labels:    [BOS, 2156, 1034, 892, 5567, EOS, -100, -100, -100, -100]
                                               ↑ PAD 位置用 -100 标记
                                                 交叉熵 loss 会忽略它们
```

> **为什么 labels 和 input_ids 一样？** 因为自回归语言模型的训练目标是：用第 t 个位置预测第 t+1 个位置。损失函数内部会自动做"右移一位"对齐（后面会看到）。

#### 5.4 分布式采样器

```python
train_sampler = DistributedSampler(train_ds) if dist.is_initialized() else None
```

> 多卡训练时，`DistributedSampler` 确保每块 GPU 拿到不同的数据子集。例如 2 卡训练 1000 条数据，GPU0 拿第 0,2,4,...条，GPU1 拿第 1,3,5,...条。

#### 5.5 GradScaler + AdamW 优化器

```python
# GradScaler：防止 float16 训练时梯度太小变成 0（梯度下溢）
scaler = torch.cuda.amp.GradScaler(enabled=(args.dtype == 'float16'))

# AdamW 优化器：Adam + 权重衰减（L2 正则化）
optimizer = optim.AdamW(model.parameters(), lr=args.learning_rate)
```

> **AdamW** 是目前训练大模型最主流的优化器。相比 SGD，它会为每个参数维护一阶矩（均值）和二阶矩（方差）的指数移动平均，自适应调整每个参数的学习率。
>
> **GradScaler** 配合 float16 使用：先把 loss 放大（scale up）再反向传播，避免梯度太小变成 0；更新参数前再缩小回来。bfloat16 不需要（数值范围够大）。

### 第 6 步：从 checkpoint 恢复状态（断点续训）

```python
start_epoch, start_step = 0, 0
if ckp_data:
    model.load_state_dict(ckp_data['model'])        # 恢复模型参数
    optimizer.load_state_dict(ckp_data['optimizer']) # 恢复优化器状态（含动量）
    scaler.load_state_dict(ckp_data['scaler'])       # 恢复梯度缩放器
    start_epoch = ckp_data['epoch']                   # 恢复 epoch 进度
    start_step = ckp_data.get('step', 0)              # 恢复 step 进度
```

> **为什么要恢复优化器状态？** 因为 AdamW 内部为每个参数维护了动量（一阶矩）和自适应学习率（二阶矩），如果只恢复模型权重而不恢复优化器，这些统计量会从零开始，导致训练抖动。

**`lm_checkpoint` 保存的完整内容：**

```python
resume_data = {
    'model': state_dict,               # 模型权重（转为 float16 节省空间）
    'optimizer': optimizer.state_dict(), # 优化器状态
    'epoch': epoch,                     # 当前 epoch
    'step': step,                       # 当前 step
    'world_size': world_size,           # GPU 数量（用于多卡变化时自动转换 step）
    'wandb_id': wandb_id               # 实验追踪 ID
}
```

> **细节**：`lm_checkpoint` 保存时会先写入 `.tmp` 文件，再 `os.replace` 原子替换。这样即使保存过程中断电，也不会损坏已有的 checkpoint（类似数据库的 WAL 机制）。

### 第 7 步：DDP 包装模型（多卡并行）

```python
if dist.is_initialized():
    # 告诉 DDP 忽略 RoPE 的预计算缓冲区（它们是固定值，不需要同步）
    model._ddp_params_and_buffers_to_ignore = {"freqs_cos", "freqs_sin"}
    model = DistributedDataParallel(model, device_ids=[local_rank])
```

> **DDP 的工作原理**：
> 1. 每块 GPU 持有一份完整的模型副本
> 2. 前向传播：各 GPU 用自己的数据子集独立计算
> 3. 反向传播：自动用 AllReduce 同步所有 GPU 的梯度（取平均）
> 4. 参数更新：因为梯度一样，所以各 GPU 的模型参数始终保持一致
>
> **前端类比**：类似 SSR 中多个 Worker 进程各自处理请求，但共享同一份状态。

### 第 8 步：训练循环（核心）

这是整个预训练的核心，分为外层循环（epoch）和内层循环（step）。

#### 8.1 外层循环：遍历 epoch

```python
for epoch in range(start_epoch, args.epochs):
    # 分布式训练时，设置 epoch 让采样器在每个 epoch 打乱数据顺序
    train_sampler and train_sampler.set_epoch(epoch)

    # 用固定种子 + epoch 生成打乱顺序（可复现）
    setup_seed(42 + epoch)
    indices = torch.randperm(len(train_ds)).tolist()

    # 计算需要跳过的 step 数（续训时生效）
    skip = start_step if (epoch == start_epoch and start_step > 0) else 0

    # SkipBatchSampler：支持跳过前 N 个 batch
    batch_sampler = SkipBatchSampler(train_sampler or indices, args.batch_size, skip)

    # 创建 DataLoader
    loader = DataLoader(
        train_ds,
        batch_sampler=batch_sampler,
        num_workers=args.num_workers,  # 多进程并行加载数据
        pin_memory=True                # 锁页内存加速 CPU→GPU 传输
    )

    train_epoch(epoch, loader, len(loader), 0, wandb)
```

**`SkipBatchSampler` 的实现：**

```python
class SkipBatchSampler(Sampler):
    def __init__(self, sampler, batch_size, skip_batches=0):
        self.sampler = sampler
        self.batch_size = batch_size
        self.skip_batches = skip_batches

    def __iter__(self):
        batch = []
        skipped = 0
        for idx in self.sampler:
            batch.append(idx)
            if len(batch) == self.batch_size:
                if skipped < self.skip_batches:
                    skipped += 1    # 跳过已训练过的 batch
                    batch = []
                    continue
                yield batch
                batch = []
```

> 续训时直接跳到上次中断的位置，不需要重新遍历已训练的数据。

#### 8.2 内层循环：单步训练（train_epoch）

这是每一步训练的完整过程，包含 7 个环节：

```
数据搬运 → 学习率调度 → 前向传播 → 反向传播 → 梯度累积/裁剪/参数更新 → 日志打印 → 模型保存
```

##### (1) 数据搬运

```python
for step, (input_ids, labels) in enumerate(loader, start=start_step + 1):
    input_ids = input_ids.to(args.device)  # CPU → GPU
    labels = labels.to(args.device)
```

> 模型在 GPU 上，数据也必须搬到 GPU 上才能计算。`pin_memory=True` + `.to(device)` 可以利用异步 DMA 传输加速。

##### (2) 学习率调度（Cosine Schedule with Warmup）

```python
lr = get_lr(epoch * iters + step, args.epochs * iters, args.learning_rate)
for param_group in optimizer.param_groups:
    param_group['lr'] = lr
```

**`get_lr` 的实现：**

```python
def get_lr(current_step, total_steps, lr):
    return lr * (0.1 + 0.45 * (1 + math.cos(math.pi * current_step / total_steps)))
```

**学习率变化曲线：**

```
lr
 ↑
 │  ╭───╮
 │ ╱     ╲
 │╱       ╲
 │         ╲
 │          ╲
 │           ╲__
 └──────────────→ step
   warmup  余弦衰减
```

> - 训练初期：学习率较小（约 0.55 × lr），避免初始梯度爆炸
> - 训练中期：学习率达到最高，加速学习
> - 训练后期：学习率逐渐衰减到约 0.1 × lr，精细调整参数
>
> 这里的实现是一个简化版的 cosine schedule（自带 warmup 效果，起始值 ≈ 0.55lr 而非 0）。

##### (3) 前向传播 + 损失计算

```python
with autocast_ctx:  # 混合精度上下文
    res = model(input_ids, labels=labels)
    loss = res.loss + res.aux_loss
    loss = loss / args.accumulation_steps  # 梯度累积：除以累积步数
```

**模型内部的前向传播详解（`MiniMindForCausalLM.forward`）：**

```python
def forward(self, input_ids, labels=None, ...):
    # 1. 跑 Transformer 主干
    hidden_states, past_key_values, aux_loss = self.model(input_ids, ...)
    #    input_ids:     [B, T]    → token id
    #    hidden_states: [B, T, H] → 每个位置的隐藏表示

    # 2. 线性映射到词表维度
    logits = self.lm_head(hidden_states)
    #    logits: [B, T, V] → 每个位置对下一个 token 的预测分布

    # 3. 计算 loss（自回归 next-token prediction）
    if labels is not None:
        shift_logits = logits[..., :-1, :].contiguous()  # 去掉最后一个时间步
        shift_labels = labels[..., 1:].contiguous()       # 去掉第一个 label
        loss = F.cross_entropy(
            shift_logits.view(-1, shift_logits.size(-1)),  # [(B*(T-1)), V]
            shift_labels.view(-1),                          # [(B*(T-1))]
            ignore_index=-100                               # 忽略 PAD 位置
        )

    return CausalLMOutputWithPast(loss=loss, logits=logits, ...)
```

**损失计算的"右移对齐"图解：**

```
位置:       0     1     2     3     4
input_ids: [BOS, "今",  "天",  "好", EOS]

logits:    [L0,   L1,   L2,   L3,  L4]  ← 模型的预测
           ↓     ↓     ↓     ↓
shift_logits: [L0,  L1,   L2,   L3]     ← 去掉最后一个

labels:    [BOS, "今",  "天",  "好", EOS]
shift_labels:    ["今",  "天",  "好", EOS] ← 去掉第一个

对齐后:
  L0 应预测 "今"
  L1 应预测 "天"
  L2 应预测 "好"
  L3 应预测 EOS
```

> **交叉熵损失**：衡量模型预测分布与真实分布的差距。loss 越小，模型预测下一个 token 越准。

##### (4) 反向传播

```python
scaler.scale(loss).backward()
```

> 1. `scaler.scale(loss)`：将 loss 放大（仅 float16 时有效），防止梯度下溢
> 2. `.backward()`：反向传播，计算每个参数的梯度（∂loss/∂param）
>
> 反向传播使用链式法则，从 loss 开始，逐层往回计算每个参数对 loss 的贡献（梯度）。

##### (5) 梯度累积 + 梯度裁剪 + 参数更新

```python
if (step + 1) % args.accumulation_steps == 0:
    # 1. 还原真实梯度（去掉 scale）
    scaler.unscale_(optimizer)

    # 2. 梯度裁剪：防止梯度爆炸
    torch.nn.utils.clip_grad_norm_(model.parameters(), args.grad_clip)

    # 3. 用优化器更新参数
    scaler.step(optimizer)

    # 4. 更新 scaler 的缩放因子
    scaler.update()

    # 5. 清零梯度
    optimizer.zero_grad(set_to_none=True)
```

**梯度累积的原理：**

```
假设 batch_size=32, accumulation_steps=8
等效 batch_size = 32 × 8 = 256

Step 1: forward + backward（梯度累积到 .grad）
Step 2: forward + backward（梯度继续累积）
...
Step 8: forward + backward → clip → optimizer.step → zero_grad
         ↑ 第 8 步才真正更新参数
```

> **为什么要梯度累积？** GPU 显存有限，无法一次性塞下很大的 batch。但大 batch 训练效果更好（梯度更稳定），所以用多次小 batch 的梯度累积来"模拟"大 batch 训练。

**梯度裁剪的原理：**

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

> 计算所有参数梯度的 L2 范数（‖g‖），如果超过 `max_norm`，就等比例缩小所有梯度：
> `g = g × max_norm / ‖g‖`
> 防止异常样本导致梯度爆炸，让训练更稳定。

if step % args.log_interval == 0:

## 五、模型架构详解

### 5.1 整体结构

```
MiniMindForCausalLM（因果语言模型）
├── model: MiniMindModel（Transformer 主干）
│   ├── embed_tokens: Embedding [V, H]       ← token id → 向量
│   ├── dropout: Dropout
│   ├── layers: ModuleList                    ← N 层 Transformer Block
│   │   └── MiniMindBlock × num_hidden_layers
│   │       ├── input_layernorm: RMSNorm
│   │       ├── self_attn: Attention          ← 多头注意力
│   │       ├── post_attention_layernorm: RMSNorm
│   │       └── mlp: FeedForward 或 MOEFeedForward
│   ├── norm: RMSNorm                        ← 最终归一化
│   └── freqs_cos / freqs_sin: Buffer        ← RoPE 预计算表
└── lm_head: Linear [H, V]                   ← 向量 → 词表概率
    └── (权重与 embed_tokens 共享)
```

### 5.2 单层 Transformer Block（MiniMindBlock）

```python
class MiniMindBlock(nn.Module):
    def forward(self, hidden_states, position_embeddings, ...):
        residual = hidden_states
        # 1. LayerNorm → Attention → 残差连接
        hidden_states, _ = self.self_attn(
            self.input_layernorm(hidden_states), position_embeddings, ...
        )
        hidden_states += residual  # 残差连接

        # 2. LayerNorm → FFN/MoE → 残差连接
        hidden_states = hidden_states + self.mlp(
            self.post_attention_layernorm(hidden_states)
        )
        return hidden_states
```

**数据流图：**

```
              input
                │
                ├──────────────────────┐
                │                      │ (residual)
         ┌──────▼──────┐              │
         │  RMSNorm     │              │
         └──────┬──────┘              │
         ┌──────▼──────┐              │
         │  Attention   │              │
         └──────┬──────┘              │
                │ ◄────────────────────┘ (add)
                │
                ├──────────────────────┐
                │                      │ (residual)
         ┌──────▼──────┐              │
         │  RMSNorm     │              │
         └──────┬──────┘              │
         ┌──────▼──────┐              │
         │  FFN / MoE   │              │
         └──────┬──────┘              │
                │ ◄────────────────────┘ (add)
                │
              output
```

### 5.3 核心子模块

#### RMSNorm（均方根归一化）

```python
class RMSNorm(torch.nn.Module):
    def _norm(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

    def forward(self, x):
        return self.weight * self._norm(x.float()).type_as(x)
```

> 相比 LayerNorm，RMSNorm 省去了均值计算，速度更快，效果几乎相同。LLaMA 系模型的标配。
>
> 公式：`RMSNorm(x) = x / sqrt(mean(x²) + ε) * γ`

#### Attention（多头注意力 + GQA + RoPE + Flash Attention）

```python
class Attention(nn.Module):
    def __init__(self, args):
        # Q/K/V/O 四个线性投影
        self.q_proj = nn.Linear(H, num_heads * head_dim, bias=False)
        self.k_proj = nn.Linear(H, num_kv_heads * head_dim, bias=False)  # KV 头数可以更少
        self.v_proj = nn.Linear(H, num_kv_heads * head_dim, bias=False)
        self.o_proj = nn.Linear(num_heads * head_dim, H, bias=False)

    def forward(self, x, position_embeddings, ...):
        # 1. 线性投影 → Q, K, V
        xq, xk, xv = self.q_proj(x), self.k_proj(x), self.v_proj(x)
        xq = xq.view(B, T, n_heads, head_dim)
        xk = xk.view(B, T, n_kv_heads, head_dim)
        xv = xv.view(B, T, n_kv_heads, head_dim)

        # 2. 应用 RoPE 旋转位置编码
        cos, sin = position_embeddings
        xq, xk = apply_rotary_pos_emb(xq, xk, cos, sin)

        # 3. GQA：K/V 头数 < Q 头数时，复制 K/V 以对齐
        xk = repeat_kv(xk, n_rep)
        xv = repeat_kv(xv, n_rep)

        # 4. 计算注意力（Flash Attention 或标准实现）
        if self.flash:
            output = F.scaled_dot_product_attention(xq, xk, xv, is_causal=True)
        else:
            scores = (xq @ xk.T) / sqrt(d_k)
            scores = scores + causal_mask  # 因果掩码：只能看到前面的 token
            output = softmax(scores) @ xv

        # 5. 输出投影
        output = self.o_proj(output)
```

> **GQA（分组查询注意力）**：Q 有 8 个头，但 K/V 只用 2 个头，每 4 个 Q 头共享 1 组 K/V。节省显存（KV Cache 更小），速度更快，效果接近全注意力。
>
> **RoPE（旋转位置编码）**：通过旋转向量来编码位置信息，而非传统的绝对位置嵌入。优势是天然支持长度外推。
>
> **因果掩码**：确保模型只能"看到前面的 token"，不能"偷看后面的答案"。上三角为 -inf 的矩阵。

#### FeedForward（SwiGLU 前馈网络）

```python
class FeedForward(nn.Module):
    def __init__(self, config):
        self.gate_proj = nn.Linear(H, intermediate_size, bias=False)
        self.up_proj   = nn.Linear(H, intermediate_size, bias=False)
        self.down_proj = nn.Linear(intermediate_size, H, bias=False)
        self.act_fn = silu  # SiLU 激活函数

    def forward(self, x):
        return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))
```

> **SwiGLU**：`down(silu(gate(x)) * up(x))`，LLaMA 系列采用的 FFN 结构，比传统的 `ReLU(xW1)W2` 效果更好。有 3 个线性层而非 2 个。

#### MOEFeedForward（混合专家前馈网络）

```python
class MOEFeedForward(nn.Module):
    def __init__(self, config):
        # N 个"专家"（每个都是一个完整的 FeedForward）
        self.experts = nn.ModuleList([FeedForward(config) for _ in range(n_routed_experts)])
        # 门控网络：决定每个 token 分配给哪几个专家
        self.gate = MoEGate(config)
        # 共享专家：所有 token 都会经过
        self.shared_experts = nn.ModuleList([FeedForward(config) for _ in range(n_shared_experts)])

    def forward(self, x):
        # 1. 门控：为每个 token 选出 top-k 个专家
        topk_idx, topk_weight, aux_loss = self.gate(x)
        # 2. 将 token 分发给对应专家计算
        # 3. 按权重加权合并各专家的输出
        # 4. 加上共享专家的输出
```

> **MoE 的核心思想**：模型有很多"专家"，但每个 token 只激活其中几个。这样总参数量很大（模型容量大），但每次计算只用一小部分参数（计算量可控）。
>
> **辅助损失（aux_loss）**：防止所有 token 都被分配到同一个专家（负载不均衡），鼓励各专家被均匀使用。

#### 权重共享（Weight Tying）

```python
# 在 MiniMindForCausalLM.__init__ 中
self.model.embed_tokens.weight = self.lm_head.weight
```

> 输入 Embedding（token → 向量）和输出 lm_head（向量 → token 概率）共享同一份权重矩阵。减少参数量，且在语义上有意义：相似的 token 在向量空间中应该靠近。

# 推理蒸馏训练流程解析（train_reason.py）

> 让模型学会"先思考、再回答"的推理链格式（`<think>...</think><answer>...</answer>`），通过对推理标记加大 loss 权重来强化格式学习。

---

## 一、什么是推理蒸馏？

普通 SFT 的助手直接给出答案，推理蒸馏让模型学会像 DeepSeek-R1 / o1 那样**先展示思考过程，再给出最终答案**。

```
普通 SFT:
  user: 3+5等于几？
  assistant: 8

推理蒸馏后:
  user: 3+5等于几？
  assistant:
    <think>
    这是一个简单的加法。3加5等于8。
    </think>
    <answer>
    8
    </answer>
```

---

## 二、与 Full SFT 的差异

| 维度 | Full SFT | 推理蒸馏 |
|------|----------|---------|
| **数据** | 普通对话 | **含 `<think>/<answer>` 标记的推理链数据** |
| **数据集** | SFTDataset | SFTDataset（相同，格式不同） |
| **损失函数** | 标准交叉熵 | **加权交叉熵**（推理标记权重 ×10） |
| **初始权重** | pretrain | **dpo**（在 DPO 之后训练） |
| **max_seq_len** | 340 | **720**（推理链更长） |
| **模型结构** | 不变 | 不变 |
| **训练循环** | 标准 | 仅 loss 计算不同 |
| **其余流程** | — | 初始化/AMP/DDP/保存等**完全一致**，略过 |

---

## 三、核心差异：加权 Loss

### 3.1 定位推理标记的 token

```python
# 预编码四个推理标记
start_of_think_ids = tokenizer('<think>').input_ids
end_of_think_ids = tokenizer('</think>').input_ids
start_of_answer_ids = tokenizer('<answer>').input_ids
end_of_answer_ids = tokenizer('</answer>').input_ids
```

### 3.2 计算加权损失

```python
# 1. 模型前向（不传 labels，手动算 loss）
res = model(input_ids)
shift_logits = res.logits[..., :-1, :]
shift_labels = labels[..., 1:]

# 2. 逐 token 计算交叉熵（reduction='none' 保留每个 token 的 loss）
loss = loss_fct(shift_logits.view(-1, V), shift_labels.view(-1)).view(shift_labels.size())

# 3. 构建 loss mask（只对助手回复计算 loss）
loss_mask = (shift_labels != -100).float()

# 4. 找到推理标记的位置
sp_ids = torch.isin(
    shift_labels.view(-1),
    torch.tensor(start_of_think_ids + end_of_think_ids
                 + start_of_answer_ids + end_of_answer_ids).to(device)
)

# 5. 将推理标记位置的权重设为 10（普通 token 权重为 1）
loss_mask_flat = loss_mask.view(-1)
loss_mask_flat[sp_ids] = 10  # ← 核心！推理标记的 loss 权重 ×10

# 6. 加权平均
logits_loss = (loss * loss_mask).sum() / loss_mask_sum
```

**权重分布图解：**

```
token:    ...  <think>  思考过程  </think>  <answer>  答案  </answer>  PAD
权重:     ...    10      1...1      10        10     1..1     10      0
                 ↑                  ↑         ↑               ↑
              推理标记的权重放大 10 倍，强制模型学会正确使用这些标记
```

> **为什么要加大推理标记的权重？** 因为 `<think>`、`</think>`、`<answer>`、`</answer>` 这四个标记在序列中出现次数很少（每条数据最多 4 个），但它们对格式正确性至关重要。如果不加权，模型可能忽略这些低频 token 的学习。

---

## 四、训练数据格式

```json
{
  "conversations": [
    {"role": "user", "content": "3+5等于几？"},
    {"role": "assistant", "content": "<think>\n这是一个加法运算。3+5=8。\n</think>\n<answer>\n8\n</answer>"}
  ]
}
```

> 数据来自大模型（如 DeepSeek-R1）生成的推理链，"蒸馏"即把大模型的推理能力通过数据传递给小模型。

---

## 五、关键超参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `from_weight` | **`dpo`** | 基于 DPO 权重（在训练链的较后阶段） |
| `max_seq_len` | **720** | 推理链比普通对话长（SFT 用 340） |
| `learning_rate` | 1e-6 | 与 SFT 相同 |
| `batch_size` | 8 | 比 SFT 的 16 更小（序列更长） |
| `data_path` | `r1_mix_1024.jsonl` | 推理链蒸馏数据 |
| 推理标记权重 | **10** | 硬编码，`<think>` 等标记的 loss 权重 |

---

## 六、在训练全景图中的位置

```
预训练 → SFT → DPO → 推理蒸馏 → GRPO/PPO/SPO（可选强化学习）
                       ↑
                    这一步！

推理蒸馏后的模型可以直接部署（具备推理链能力），
也可以继续用 GRPO/PPO/SPO 进行强化学习进一步优化。
```
